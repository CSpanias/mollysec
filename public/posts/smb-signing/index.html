SMB Signing and NTLM Relay Explained

How SMB signing works, why it exists, and its role in preventing NTLM relay attacks.
June 20, 2026 · mollysec

Introduction#

TL;DR on SMB#

In Active Directory environments, Server Message Block (SMB) is heavily used for authentication, file sharing, Group Policy distribution, and administrative operations, making its security critical.

SMB Signing#

SMB signing is a security mechanism used to confirm the client’s and server’s identities as well as the integrity of the message.An oversimplification of the process is this:

  1. A session key is established between the server and the client during the authentication steps.
  2. Each message is then hashed.
  3. Each hash is signed signed using the session key.

The default behaviour on Windows systems depends on mostly two variables: if the machine is a Domain Controller (DC) and if we are asking from the server (when other machines connect to it) or client (when it connects to other machines) side.

The above “inconsistency” actually makes sense once we have a think about the role of each system. DCs are the most important components of the domain; compromising a DC has much more severe implications than compromising a single server. As a result, they must prioritise security and not convienence. On the other hand, non-DC machines (servers or workstations) must maintain compatibility with a wide range of systems (e.g. legacy devices, embedded systems, etc.) that may not support SMB signing at all. Thus, they default to a more permissive configuration.

Let’s now see what SMB signing prevents attackers from doing.

NTLM Relay#

Let’s say we are performing an internal test, we know that the LLMNR protocol is enabled, and we are trying our luck with an LLMNR poisoning attack.

We were lucky to capture the hash of an Administrator, but, unfortunately, it is not crackable. Our only other option is to use it as it is, i.e., check if an NTLM relay attack is possible in the environment.

Mitigation#

It is recommended to configure systems to require SMB signing on both clients and servers, particularly within domain environments. This can typically be enforced via Group Policy under security settings related to Microsoft network client and server communications. In addition, message signing can be configured as ‘Required’ in the host’s configuration. Please see Microsoft’s guidance within the references below for full details on enforcing required signing.
